# YouTubeのnote収益化ノウハウを公式情報で選別した

最終更新日：2026-10-07
対象：YouTube上のnote運用・収益化の解説動画（公開日 2026-04-07〜2026-10-07）
関連ファイル：`note_knowledge.md`（知識ベース本体）／`note_sources.md`（動画・発信者・公式情報源の一覧）

2026年4〜10月に公開されたnote運用・収益化の動画38本を全文確認し、note公式情報で裏取りした結果、**信頼して使えるノウハウの中心は「公式が方針として示していること」と「複数の発信者が独立に同じことを言っていること」の重なりにある**と分かった。具体的には、一次情報（自分の体験・数字）を軸にAIは道具として使うこと、タイトル・冒頭で「誰のどんな悩みが解決するか」を明示すること、悩みの深いテーマを昔の自分の経験から選ぶこと、検索とnote内回遊で見つけてもらう導線を作ることの4点で、公式データ（記事PVの73%がnote内回遊と検索、SNS経由は8%）とも整合する。一方で、発信者の売上はnoteの外から確認する方法がなく、成功を語る発信者の多くは主な収益をnote外（講座・自社商品・アフィリエイト）で得ていた。数字付きの失敗例2件（SNSなし・フォロワー0から3か月で約2万円、32日で0円）は、「始めればすぐ稼げる」という期待を修正する材料になる。「note公式発表」をうたう動画6本のうち、公式記事を正確に要約していたのは2本だけで、数字の出典は必ず一次ソースで確かめる必要がある。この知識ベースは、項目ごとに出典・信頼度・最終確認日を持たせ、再調査で追記・訂正できる形にした。

## 信頼性チェックの方法

動画ごとに次の4つを確認した。第一に、**発信者の実績**：概要欄のnoteアカウントURLから note API（`/api/v2/creators/{urlname}`）でフォロワー数・記事数を、メンバーシップ人数を `/circle/members` の totalCount で取得し、動画内の発言と照合した。動画内の売上はすべて「本人の申告（未検証）」とし、画面で見せたという話も検証済みにはしていない。第二に、**公式情報との照合**：仕様・数字に関わる主張は、note公式ヘルプ（help-note.com のAPIで本文と更新日を取得）、note公式・note編集部の記事（note APIで本文と公開日を取得）、note株式会社のプレスリリース、IR資料・決算説明会の書き起こしと照合した。第三に、**独立した発信者どうしの一致**：同じ発信者の複数動画は1と数え、一致した独立発信者の数を「複数ソース一致」として記録した。第四に、**誇張と誘導**：根拠のない割合（「9割が…」）、タイトルの数字と本編の食い違い、商材・LINEへの誘導を記録した。再生数は信頼の根拠にしていない。

信頼度は、公式情報を★★★★★、公式の裏付けがあるか実績を確認できる発信者を含む2人以上が一致したものを★★★★☆、有用だが個人の経験中心のものを★★★☆☆とし、★★☆☆☆以下は知識ベースのセクション20（未検証情報）にだけ置いた。

## 主な発見

**公式が「何を評価するか」をかなり具体的に言うようになった。** 2026年のnote公式は、検索・AI対策の9ポイント（一次情報、AIは活用してよいが無編集の大量公開はNG、見出し、内容が想像できるタイトル、プロフィール、ALT、出典、やらなくてよいこと、YMYL）を示し（[note編集部](https://note.com/notemag/n/nac99c25b8271)）、CXOはおすすめの優先順位の1位を「人間による生の一次情報」とした（[深津貴之](https://note.com/fladdict/n/n5b78bb223b35)）。レコメンドエンジンはLLMで記事を約4,000の基本タグに分類し、「中身が空っぽ」な記事も分類できると説明している（[決算説明会書き起こし](https://contents.xj-storage.jp/xcontents/AS05592/38626485/5a79/4cfe/9130/eadce375689f/20260709104259655s.pdf)）。YouTuberの「一次情報を書け」「AIの出力をそのまま出すな」という助言は、この公式方針と一致しており、今回最も裏付けの強いノウハウになった。

**集客の主役はSNSから検索とnote内回遊に移っている。** 記事PVの73%がnote内回遊と検索で、SNS経由は20%から8%に下がった（[note株式会社](https://note.jp/n/nce2c203cc6fb)）。レコメンド刷新後はカテゴリページ経由の表示とPVが大きく伸びた（[note IR](https://note.com/note_ir/n/n96c288a82213)）。ただしこれはPVの構成比で、購入の構成比ではない。数字付きの失敗例（あき、シズマ）は、読者基盤なしで始めると売上はかなり小さいことを示しており、「SNS不要」はそのまま初心者に当てはめられない。

**「note副業で稼ぐ」の中身は発信者ごとに違う。** 成功を語る発信者の多くが、主な収益をnote外に置いていると自ら述べている（例：あきの2025年は有料note約89万円に対しコンテンツ販売約500万円、[本人のnote記事](https://note.com/akio360/n/ne87b605b65f0)）。発信者の実績として外部から確かめられるのは、noteのフォロワー数・記事数・メンバー数・記事の価格とスキ数だけで、メンバー数まで確認できたのは3人だった。

**「公式」の看板は当てにならない。** 「公式」をタイトルに入れた6本のうち、公式記事を正確に要約していたのは2本。他は、公式の文言を広げて解釈する（スパム対策→「AI記事の排除」）、出典が確認できない数字を「公式」とする、などがあった。逆に、調査の途中で「出典不明」とした数字のうち3つ（SNS 8%、記事の約40%が1年後も読まれる、MAUの規模）は、別の公式資料で確認できた。主張を捨てる前にも、公式資料を複数当たる必要がある。

## 限界

- **売上を検証できない**：noteは売上を公開しておらず、発信者の売上・販売部数はすべて申告のまま。noteで確認できる実績はフォロワー数・記事数・メンバー数・記事の存在と価格に限られる。
- **ジャンルの偏り**：分析した38本は副業・稼ぎ方・AI系の発信者が中心で、エッセイ・創作・子育て・趣味などのジャンルの事例はほとんどない。
- **サンプルの選び方**：題名でスクリーニングしたため、題名に「note」を含まない良質な動画を取りこぼしている可能性がある。期間内の候補184本のうち146本は内容を見ていない。
- **自動字幕の誤変換**：数字や固有名詞が崩れている箇所がある（例：売上額、人名）。
- **取得できなかった公式情報**：note公式X（@note_PR）の投稿、深津氏記事の3・4番目の原文、プレスリリース（2026-02-12）内の図の数値（「検索42%」の確認）、決算説明会書き起こしの文字化け部分、規約の一部（自己購入・売上公開・外部誘導・AIエージェントによる操作）。
- **再生数・登録者数**：ひらかわのチャンネル登録者数は818と8,180で記録が食い違い、確認できない。
- **時点**：仕様・数字は2026-10-07時点。公式のカイゼン一覧は毎月追記される。

## 次回更新時の手順

1. **候補の収集**：前回と同じ32の検索語でYouTubeを検索する（検索語の一覧はこのファイル末尾の「付録：今回使った検索語（32個）」を参照。検索語を変えた場合は付録を更新する）。取得は yt-dlp を使い、YouTubeのボット確認を避けるため `web_embedded` クライアントを指定する。
   ```
   yt-dlp --flat-playlist --print id "ytsearch50:note 収益化"
   yt-dlp --skip-download --extractor-args "youtube:player_client=web_embedded" \
     --print "%(id)s\t%(upload_date)s\t%(view_count)s\t%(channel_follower_count)s\t%(duration)s\t%(channel)s\t%(title)s" \
     "https://www.youtube.com/watch?v={動画ID}"
   ```
2. **スクリーニング**：前回の最終更新日以降に公開された動画だけを対象にし、題名に「note／ノート」を含むものから、内容が運用・収益化に関係するものを選ぶ。`note_sources.md` セクションDの未確認候補も見直す。
3. **文字起こし**：自動字幕と概要欄を取得し、最初から最後まで読む。
   ```
   yt-dlp --skip-download --write-auto-subs --sub-langs ja --sub-format vtt --write-description \
     --extractor-args "youtube:player_client=web_embedded" -o "subs/%(id)s.%(ext)s" \
     "https://www.youtube.com/watch?v={動画ID}"
   ```
   HTTP 429（アクセス過多）が出たら時間をおいて再実行する。
4. **発信者の実績確認**（取得日を必ず記録）：
   - フォロワー数・記事数：`curl -s "https://note.com/api/v2/creators/{urlname}"`（followerCount、noteCount）
   - メンバーシップ人数：`curl -s "https://note.com/api/v2/creators/{urlname}/circle/members"`（totalCount）。プランは `/circle/plans`
   - 記事一覧：`/api/v2/creators/{urlname}/contents`。個別記事の価格・スキ数・公開日：`https://note.com/api/v3/notes/{記事キー}`
   - 前回の数値（`note_sources.md` セクションB）と比べ、変化を記録する。
5. **公式情報の再確認**：
   - ヘルプ記事の本文と更新日：`https://www.help-note.com/api/v2/help_center/ja/articles/{記事ID}.json`（edited_at）
   - 2026年のカイゼン一覧（https://note.com/info/n/nb50a11d765b8 ）で前回以降の変更を確認
   - note編集部（notemag）、note公式（info）、note株式会社（note.jp、PR TIMES）、IR（決算資料・書き起こし）の新着を確認
6. **知識ベースの更新**（`note_knowledge.md` の更新ルールに従う）：既存項目は消さない。同じ内容は既存項目に出典を追加して「複数ソース一致」「情報更新日」を更新する。仕様が変わった項目は本文を更新し、変更前の内容をセクション19へ移す。食い違いは両論を記録する。未確認の主張はセクション20へ。確認した項目の「最終確認日」を更新する。
7. **3ファイルの整合**：`note_sources.md`（セクションA〜D）と、このレポートの件数・TOP10・古い情報・意見が分かれる点を更新する。
